# メール送信サービスを用意する

Pagewright にはパスワードがなく、ログインには毎回メールで届くリンクを使います。
そのため、**メールを送れないとログインできません**。導入の前に、メールを送る手段を用意します。

## Pagewright が送るメール

| メール | 送り先 | 件名 |
| --- | --- | --- |
| ログイン用のリンク | ログインしようとした人 | Pagewright ログイン用のリンク |
| お問い合わせの通知 | 「サイトの設定」の送り先（空欄なら、そのサイトの管理者全員） | 【サイトの名前】お問い合わせがありました |
| お問い合わせの自動返信 | お問い合わせフォームに入力されたメールアドレス（同じアドレスへは1日3通まで） | 【サイトの名前】お問い合わせを受け付けました |

差出人は、どれも `.env` の `PAGEWRIGHT_MAIL_FROM` です。

## メール送信サービスとは

ほかのサーバーへメールを届ける仕事を引き受けてくれるサービスです。「SMTP」という決まった方法でつなぎます。
自分のサーバーから直接メールを送ると、迷惑メールと見なされたり、届かなかったりしがちです。また、多くの VPS やクラウドでは、メールを直接送るのに使う 25 番ポートがふさがれています。
そのため、メール送信サービスを使い、**587 番ポート**（送信用の決まったポート）でつなぎます。

用意するものは次の4つです。

| `.env` の項目 | 書くもの |
| --- | --- |
| `PAGEWRIGHT_SMTP_ADDR` | サービスの SMTP サーバーとポート（例：`smtp.example.net:587`） |
| `PAGEWRIGHT_SMTP_USERNAME` | サービスが指定するユーザー名 |
| `PAGEWRIGHT_SMTP_PASSWORD` | サービスが発行するパスワード（API キーなど） |
| `PAGEWRIGHT_MAIL_FROM` | 差出人。例：`ウェブサイト管理 <no-reply@example.co.jp>`。名前の部分は受け取った人の受信箱に出るので、何のメールかわかる名前にします |

### サービスの例

よく使われるサービスの例です。名前や手順は変わることがあるので、**かならずサービスの最新の説明を確かめてください**。料金もサービスの案内で確かめます。

| サービス | SMTP サーバー | ユーザー名・パスワード |
| --- | --- | --- |
| SendGrid | `smtp.sendgrid.net:587` | ユーザー名は `apikey` という文字そのもの。パスワードは SendGrid で作った API キー |
| Amazon SES | `email-smtp.<リージョン>.amazonaws.com:587`（例：東京は `ap-northeast-1`） | SES の画面で作る「SMTP 認証情報」（AWS のアクセスキーとは別のもの）。使い始めは、確認済みのアドレスにしか送れない状態（サンドボックス）なので、本番で使う申請をします |
| Google Workspace の SMTP リレー | `smtp-relay.gmail.com:587` | Google Workspace の管理コンソールで SMTP リレーを有効にして設定します |

社内にメールの中継サーバーがあるなら、それも使えます。

## 差出人のドメインを登録する（SPF・DKIM）

`PAGEWRIGHT_MAIL_FROM` のドメイン（例：`example.co.jp`）を、メール送信サービスに登録します。
登録の途中で、サービスが **DNS に足すレコード** を表示するので、そのとおりにドメインの DNS に足します。これをしないと、メールが迷惑メールに入ったり、届かなかったりします。

- **SPF**：「このドメインのメールは、このサービスから送ります」と DNS で宣言するしくみです
- **DKIM**：メールに電子的な署名を付け、途中で書き換えられていないことと、ドメインの持ち主が送ったことを確かめられるようにするしくみです

## 暗号化の設定（`PAGEWRIGHT_SMTP_TLS`）

メール送信サービスとのやりとりは暗号化します。ふつうは **`.env.example` のまま（`starttls`）** にしておきます。

| 値 | 使うとき |
| --- | --- |
| `starttls`（`.env.example` の値） | 587 番ポートのサービス。つないでから暗号化に切り替えます（STARTTLS）。暗号化できないサーバーには送りません |
| `implicit` | 465 番ポートのように、最初から暗号化して話すサーバー |
| 空 | 同じマシンや社内の、暗号化しない中継サーバーへ送るときだけ。サーバーが対応していれば暗号化し、対応していなければ暗号化せずに送ります |

ユーザー名とパスワードは、暗号化した通信の上でしか送りません。

## 送れるか確かめる

導入が終わったら（「[導入](./setup.md)」の手順6）、次のように確かめます。

1. 管理画面からいったんログアウトし、ログイン画面で自分のメールアドレスを入れて「ログイン用のリンクを送る」を押します
2. メールが届くか確かめます（迷惑メールのフォルダも）
3. 届かないときは、送信のエラーがログに出ていないか見ます

   ```sh
   docker compose logs app | grep -i mail
   ```

ログにエラーがないのに届かないときは「[困ったとき](./troubleshooting.md#メールは送れたのに届かない)」を見てください。
メールが届かなくても、コマンドでログイン用のURLを出せます（「[困ったとき](./troubleshooting.md#ログイン用のメールが届かない)」）。
