# はじめに（必要なもの）

会社のWebサイトを1つ、自社で用意したサーバーで動かすための手順です。
サーバーに入って作業する人（このドキュメントでは「サーバーの担当者」と呼びます）に向けて書いています。
記事を書く人向けの説明は「[使い方](../guide/)」にあります。

::: warning いまの状態
Pagewright はまだ最初の版（v0.1.0）を出す前です。それまでは試用向けで、大事なサイトの本番には使わないでください。
:::

## この順に進めます

左のメニューの「最短の道」を上から順に進めると、サイトを公開して、ふだんの運用ができるところまで終わります。
作業そのものは、慣れていれば1〜2時間ほどです（DNS の反映や、メール送信サービスの申し込みの審査を待つ時間は別です）。

1. このページで、必要なものをそろえる
2. [メール送信サービスを用意する](./mail.md)（ログイン用のメールを送るのに必要）
3. [導入](./setup.md)
4. [使う人に渡すもの](./handover.md)
5. [バックアップと復元](./backup.md)
6. [アップデート](./update.md)（新しい版が出たとき）
7. [困ったとき](./troubleshooting.md)

WordPress のサイトから移るときは、導入のあとに「[WordPress からの移行](./wordpress.md)」も行います。
知らない言葉が出てきたら「[用語集](./glossary.md)」を見てください。

## できあがる形

```
閲覧者 ─HTTPS→ caddy ─→ nginx ─┬→ 公開サイト（書き出した静的ファイル）
                                └→ 管理画面（app） ─→ db（PostgreSQL）
```

- **公開サイト**（例：`www.example.co.jp`）は、管理画面で公開したときに書き出されるファイルです。管理画面が止まっていても表示され続けます。
- **管理画面**（例：`admin.example.co.jp`）は、記事を書いたり公開したりする画面です。
- HTTPS の証明書は Caddy が自動で取得・更新します。
- データベース（PostgreSQL）も含めて、Docker Compose でまとめて動かします。

## 必要なものチェックリスト

- [ ] **Linux のサーバー1台**（VPS やクラウドのサーバー）。Docker が動く Linux なら使えます（おすすめは、最近の Ubuntu LTS など）。CPU は x86_64 か arm64。メモリ 2GB 以上、ディスク 20GB 以上を目安に（画像が多ければ増やす）
- [ ] **sudo を使える普通のユーザー**で作業できること
- [ ] **Docker Engine 27 以降と Docker Compose v2**。入れ方は [Docker の公式の手順](https://docs.docker.com/engine/install/) を見てください。入れたら `docker version`（Server の Version）と `docker compose version` で確かめます
- [ ] 作業するユーザーが **`docker` グループ**に入っていること。手順の `docker` コマンドは sudo なしで書いています

  ```sh
  sudo usermod -aG docker "$USER"
  ```

  入れたら、**一度ログアウトしてログインし直します**（入れ直すまで効きません）。入れないときは、手順の `docker …` を `sudo docker …` と読み替えます
- [ ] **`git` と `openssl`**（Ubuntu なら `sudo apt install git openssl`）
- [ ] **ドメイン1つと、その下の名前2つ**。例：`example.co.jp` を持っていて、公開サイトを `www.example.co.jp`、管理画面を `admin.example.co.jp` にする。その DNS を自分で設定できること
- [ ] **ポート 80 と 443 が外から届くこと**（証明書の取得と、サイトの表示に使う）。次の「ポートを開ける」を見てください
- [ ] **メール送信サービス**（SMTP）。ログイン用のリンクを送るのに使います。多くの VPS では 25 番ポートからメールを送れないので、587 番ポートで送れるサービスを使います（「[メール送信サービスを用意する](./mail.md)」）

## ポートを開ける

80 番と 443 番を、2か所で開けます。

1. **サーバー会社やクラウドの管理画面のファイアウォール**（「セキュリティグループ」「パケットフィルター」などと呼ばれます）で、80 番（TCP）と 443 番（TCP と UDP）への接続を許可します
2. **サーバーの中のファイアウォール**を使っているときは、そこでも許可します。Ubuntu の `ufw` なら次のとおりです（SSH で入れなくならないよう、`OpenSSH` も許可しておきます）

   ```sh
   sudo ufw allow OpenSSH
   sudo ufw allow 80/tcp
   sudo ufw allow 443
   sudo ufw status
   ```

## この構成でできないこと

- 2つ目以降のサイトの公開は、設定ファイルを手で足す必要があります（「[2つ目のサイト](./second-site.md)」）
- 管理画面を社内ネットワークの中だけに置くこと（Caddy の設定で IP 制限をかけるなどの工夫が必要です）
