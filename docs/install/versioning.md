# 版の付け方と互換性

Pagewright の版は `メジャー.マイナー.パッチ`（例：`0.3.1`）の3つの数字で表します。[Semantic Versioning](https://semver.org/lang/ja/) にならいます。
使っている版は `pagewright version`（Docker Compose なら `docker compose run --rm cli version`）で確かめられます。

## 1.0 までの決まり（0.x）

テーマと本体の約束などがまだ固まっていないので、1.0 までは次のようにします。

| 上がる数字 | 例 | 中身 | アップデートの前に |
| --- | --- | --- | --- |
| パッチ | 0.3.0 → 0.3.1 | 不具合とセキュリティの修正だけ。下の「互換性を壊す変更」は入れない | バックアップを取れば、そのまま上げてよい |
| マイナー | 0.3.1 → 0.4.0 | 機能の追加。互換性を壊す変更が入ることがある | [変更履歴](https://github.com/kom3da/pagewright/blob/main/CHANGELOG.md) のその版の「注意」を読む |

- 互換性を壊す変更は、必ず変更履歴の「注意」に、何をすればよいかと一緒に書きます
- マイナーを飛ばして上げても（0.2 → 0.4 など）かまいません。データベースの変更は、途中の版の分も順に行われます
- 修正は最新の 0.x にだけ入れます。古い版への持ち込み（バックポート）はしません（[SECURITY.md](https://github.com/kom3da/pagewright/blob/main/SECURITY.md)）

1.0 からは、互換性を壊す変更はメジャー（1.x → 2.0）でだけ行います。

## 互換性を壊す変更

次のどれかに当たる変更を「互換性を壊す変更」とします。

| 対象 | 壊す変更の例 | 壊さない変更の例 |
| --- | --- | --- |
| データベース | 元に戻すとデータが消えるマイグレーション、時間がかかる・手作業が要るマイグレーション | 表や列の追加 |
| 本文の形式（`schema/`） | 本文JSONのスキーマのバージョンが上がる（古いデータは自動で変換されるが、古い版の本体では読めなくなる） | ブロックや装飾の属性を任意で足す |
| テーマと本体の約束（`docs/themes.md`） | テンプレートに渡すデータ・関数・`theme.json` の項目を消す、名前や意味を変える | 新しいデータや関数を足す |
| 設定 | 環境変数（`PAGEWRIGHT_*`）を消す・名前や意味を変える・必須の設定を増やす | 初期値のある設定を足す |
| コマンド | サブコマンドや引数を消す・名前や意味を変える | サブコマンドや引数を足す |
| 導入一式（`deploy/`） | `compose.yaml` のサービス・ボリューム・`.env` の項目の変更で、手元の設定を直す必要があるもの | 手元の設定を直さずに使える変更 |
| 公開サイト | 書き出すページのURLが変わる（旧URLからのリダイレクトがあっても、変更履歴に書く） | ページの見た目の調整 |

管理画面が使うAPI（`/api/`）は、同じ版の管理画面のためのもので、外から使う約束はしません（いまの形は「v0」）。版の間で予告なく変わることがあり、互換性を壊す変更には数えません。外から使えるAPIを用意するときは、別に版を付けます。

## 前の版に戻す

**データベースの変更（マイグレーション）は、本体の版を戻しても元に戻りません。** 新しい版で起動すると、その版のマイグレーションが自動で行われ、古い版の本体はそのデータベースで正しく動くとは限りません。

アップデートの後に前の版へ戻すときは、アップデートの前に取ったバックアップから復元してください（「[バックアップと復元](./backup.md)」「[アップデート](./update.md)」）。

## Docker イメージのタグ

リリースのたびに、`ghcr.io/kom3da/pagewright` に次のタグを付けます。

| タグ | 指す版 | 使い方 |
| --- | --- | --- |
| `0.3.1` | その版だけ | **おすすめ。** 自分で決めたときにだけ上がる |
| `0.3` | 0.3 の最新のパッチ | 修正だけは自動で取り込みたいとき（`docker compose pull` のたびに変わる） |
| `latest` | 最新の版 | 使わない。マイナーが上がると、互換性を壊す変更が知らないうちに入る |

`-rc.1` などの付いた試験版（プレリリース）には `0.3` と `latest` は付きません。
